# Glossary

Each term in plain words, with the chapter that introduces it. [Appendix A](appendix-pekko-names.md) maps the Apache Pekko names.

- **Actor.** Something that handles messages one at a time and keeps its own state, like a person at a desk with an inbox. Nothing else can touch that state. [Chapter 1](01-actors.md#the-idea)
- **Actor system.** The building the actors live in. It starts the guardian, hosts the infrastructure under `/system`, and shuts everything down in order. [Chapter 2](02-actor-system.md#the-idea)
- **Ask.** Sending a message that carries a reply address, then awaiting the answer, with a timeout. [Chapter 1](01-actors.md#ask-and-reply)
- **Behavior.** What an actor does with its next message. A handler returns the next behavior, which is how an actor's state changes. [Chapter 1](01-actors.md#the-idea)
- **Bootstrap.** Forming a cluster with no seed list. Each node finds its peers through discovery and asks them whether a cluster exists. If none does, the node with the lowest address starts one. [Chapter 8](08-management-and-kubernetes.md#the-idea)
- **Child.** An actor started by another actor, its parent. Stopping a parent stops its children first. [Chapter 2](02-actor-system.md#the-idea)
- **Cluster.** Several actor systems with the same name, in different processes or on different machines, that share one membership list. [Chapter 5](05-cluster.md#the-idea)
- **Cluster singleton.** One actor for the whole cluster, run on the oldest node, and reached from every node through a proxy. [Chapter 6](06-singleton.md#the-idea)
- **Coordinated shutdown.** The fixed checklist of phases a system runs when it stops, from "stop taking requests" to "stop the actors". Each part of the program adds its tasks to the right phase. [Chapter 2](02-actor-system.md#coordinated-shutdown)
- **Coordinator.** The cluster singleton that decides which node hosts each shard, and moves shards when nodes join or leave. [Chapter 7](07-sharding.md#the-idea)
- **Dead letter.** A message that could not be delivered, because its actor had stopped, its mailbox was full, or it was sent across the network to a path with no actor. It is published on the event stream. [Chapter 1](01-actors.md#dead-letters-and-logging)
- **DeathWatch.** One actor asking to be told, with a `Terminated` signal, when another actor stops. [Chapter 1](01-actors.md#children-stopping-and-deathwatch)
- **Decorator.** A function written with `@` above a `def`, which takes your function and hands it to whoever calls it later: the runtime for `@Behaviors.receive`, the actor's context for `@ctx.pipe_to_self`. [Chapter 1](01-actors.md#decorators)
- **Discovery.** The lookup that lists where a service's nodes are: the Kubernetes API server, or a fixed list. [Chapter 8](08-management-and-kubernetes.md#the-idea)
- **Entity.** One of many small actors that sharding addresses by id, such as one cart per customer. It starts on its first message. [Chapter 7](07-sharding.md#the-idea)
- **Event stream.** The system's notice board: the runtime publishes dead letters, unhandled and dropped messages on it, and actors subscribe to the kinds they want. [Chapter 1](01-actors.md#dead-letters-and-logging)
- **Gossip.** How nodes share the membership list. Every second each node tells another what it knows, and a clock on each version says which version is newer. [Chapter 5](05-cluster.md#the-idea)
- **Guardian.** The first actor, the one you pass to `ActorSystem(...)`. The system itself is a ref to it. [Chapter 2](02-actor-system.md#the-idea)
- **Hand-over.** When the oldest node leaves, it stops its singleton and tells the next oldest to start one. Shards move the same way, by **hand-off**. [Chapter 6](06-singleton.md#the-idea), [chapter 7](07-sharding.md#how-it-works)
- **Health check.** An HTTP route that Kubernetes calls to ask a pod whether it is alive (`/alive`) or ready for traffic (`/ready`). [Chapter 8](08-management-and-kubernetes.md#the-idea)
- **Leader.** The reachable node with the lowest address. It is the only node that changes members' statuses. [Chapter 5](05-cluster.md#the-idea)
- **Mailbox.** An actor's queue of messages waiting to be handled. [Chapter 1](01-actors.md#the-idea)
- **Management.** The small HTTP server on each node that serves the health checks, read-only cluster routes and the bootstrap. [Chapter 8](08-management-and-kubernetes.md#the-idea)
- **Manual time.** A clock for tests that moves only when the test says so, so a test can fire an hour-long timer at once. [Chapter 12](12-testing.md#a-third-example-a-timer-with-manual-time)
- **Member status.** Where a node is in its life in the cluster: joining, up, leaving, exiting, removed, or down. [Chapter 5](05-cluster.md#gossip-a-leader-and-agreement)
- **Message.** A value sent to an actor, usually a frozen dataclass. [Chapter 1](01-actors.md#the-idea)
- **Node.** One actor system in a cluster, usually one process. [Chapter 5](05-cluster.md#the-idea)
- **Passivation.** Stopping an idle entity to free its memory. Its next message starts it again. [Chapter 7](07-sharding.md#sharding-in-one-process)
- **Path.** An actor's place in the family tree, such as `ohra://shop/user/alice`. With remoting it includes a host and a port. [Chapter 2](02-actor-system.md#the-idea)
- **Persisted behavior.** A behavior that saves its state to a store before it replies, and loads it again when it starts. [Chapter 3](03-persistence.md#the-idea)
- **Proxy.** The ref on each node that forwards to the cluster singleton, wherever it runs at the moment. [Chapter 6](06-singleton.md#the-idea)
- **Receptionist.** The registry where actors register under a `ServiceKey`, and where others look them up. [Chapter 2](02-actor-system.md#receptionist)
- **Recovery.** Starting a persisted actor from its last saved state, in one read. [Chapter 3](03-persistence.md#the-idea)
- **Ref.** An actor's address, `ActorRef[T]`, where `T` is the type of message it accepts. It is the only way to reach an actor. [Chapter 1](01-actors.md#the-idea)
- **Remotable.** The mark on a message type that may cross the network. [Chapter 4](04-remoting.md#the-idea)
- **Remoting.** Reaching actors in other processes through ordinary refs. [Chapter 4](04-remoting.md#the-idea)
- **Revision.** The number of a saved state. A save must take the next number, so two copies of an actor cannot overwrite each other's saves. [Chapter 3](03-persistence.md#the-idea)
- **Scheduler.** The system's clock for everything that waits: timers, backoff delays, ask timeouts. Tests can swap it for manual time. [Chapter 2](02-actor-system.md#how-it-works)
- **Seed node.** A node that a new node contacts to join the cluster. [Chapter 5](05-cluster.md#a-first-example)
- **Shard.** A group of entity ids, chosen by a hash, that lives on one node and moves as a unit. [Chapter 7](07-sharding.md#the-idea)
- **Sharding.** Spreading entities over the nodes and reaching each one by id, wherever it lives. [Chapter 7](07-sharding.md#the-idea)
- **Split-brain resolver.** The part of the cluster that decides when an unreachable node is gone, and removes it, so that a network split cannot leave two clusters. [Chapter 5](05-cluster.md#split-brain-resolver)
- **Stash.** A buffer where an actor keeps messages it is not ready for, to handle them later. [Chapter 1](01-actors.md#timers-and-stash)
- **Store.** Where persisted state is kept: `SqliteStore`, `PostgresStore` or `InMemoryStore`. [Chapter 3](03-persistence.md#the-idea)
- **Supervision.** What happens when a handler raises: the actor stops, unless a supervisor says to resume or restart it. [Chapter 1](01-actors.md#supervision)
- **Tell.** Sending a message without waiting for anything back. [Chapter 1](01-actors.md#the-idea)
- **Test probe.** A stand-in actor in a test: pass its ref where the actor under test sends messages, then await what arrives. [Chapter 12](12-testing.md#the-idea)
- **Timer.** A message an actor schedules for itself, once or repeatedly. [Chapter 1](01-actors.md#timers-and-stash)
- **Unreachable.** A node that has stopped answering heartbeats. It is suspected, not yet removed. [Chapter 5](05-cluster.md#the-idea)
