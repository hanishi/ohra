# Sharding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entity-per-id actors with create-on-demand, passivation and lifecycle buffering, as Pekko's `ClusterSharding` region behaves inside one node.

**Architecture:** One new module `pekko_py/sharding.py`: value types (`EntityTypeKey`, `Entity`, `EntityContext`, `ShardingEnvelope`, `Passivate`, `GetShardRegionState`, `CurrentShardRegionState`), an `EntityRef` that wraps messages in envelopes, and a region behavior built from `Behaviors.setup` + `receive` that owns entities as children. `cell.py` is untouched: watching, `ctx.stop`, `ctx.timers` and child naming already provide the lifecycle hooks.

**Tech Stack:** stdlib only (`urllib.parse.quote`).

**Spec:** `docs/superpowers/specs/2026-10-24-sharding-design.md`

## Global Constraints

- Python `>=3.12`, core `dependencies = []`, `uv run pytest` and `uv run pyright` (strict) green after every task.
- Pekko names in snake_case; every deviation in the spec's last section lands in the README deviations list (Task 4).
- `cell.py` is not modified.
- Commits: hanishi commits on request. Do not run `git commit`; leave the tree clean and ready and say so.
- Tests follow `tests/test_routers.py`: frozen dataclass messages, one behavior per test, `eventually` from `tests/util.py`, no sleeps longer than 50ms.

## Review Focus

- An entity id containing `/` or starting with `$` must work; `spawn_child` rejects such names, so the region must quote. Task 1, `test_entity_ids_may_contain_any_characters`.
- A message that arrives while the entity is stopping must reach the recreated entity, not a dead letter. Task 2, `test_messages_during_passivation_are_buffered_and_replayed_in_order`.
- A second `Passivate` for an id already passivating must be ignored, not stop a recreated entity. Task 2, `test_duplicate_passivate_is_ignored`.
- The idle timer must restart on every message, so a steadily used entity never passivates. Task 3, `test_idle_timer_restarts_on_each_message`.
- Terminating the system with live and passivating entities must leak nothing; the conftest check covers every test, and Task 2's buffering test ends with entities in both states.

- Internal: `type _RegionCmd[T] = ShardingEnvelope[T] | GetShardRegionState | _Passivate | _Idle` where `_Passivate(entity_path: str)` is produced by a `ctx.message_adapter` from `Passivate` and `_Idle(entity_id: str)` is the timer message (Task 3 uses it; define it now so the union is stable).

- [ ] **Step 3: Implement passivation in the region**

`_passivate(entity_id)`: no-op if already in `passivating` or unknown; else move to `passivating[entity_id] = []`, cancel the idle timer for the id, then `entity.tell(stop_message)` if set else `ctx.stop(entity)`. Envelope for a passivating id appends to the buffer. On `Terminated(ref)`: `entity_id = ids_by_path.pop(ref.path)`, drop from `entities`, pop the buffer; if non-empty, create the entity again and deliver each buffered message in order. `ChildFailed` is a `Terminated`, so the same branch handles failure.
